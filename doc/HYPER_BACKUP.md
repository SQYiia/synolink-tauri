# Hyper Backup 创建与执行管理（0.1.19 预览）

## 本批功能

- 新建 NAS 本地／USB 共享文件夹目标的多版本 `.hbk` 任务：名称、多选源目录、目标共享文件夹、备份目录名和压缩选项。
- 新任务为手动执行，不启用备份定时、完整性检查定时、自动版本清理或客户端加密。系统配置备份沿用 Hyper Backup 的 `bkp_config` 设置；未选择套件应用备份。
- 已有任务可立即备份、暂停、继续及取消；包含在 DSM 中创建的其他目标类型任务，但必须由 NAS 返回兼容的可操作状态。
- 实时状态每 10 秒刷新，状态详情最多并发两项。当前状态、上次结果和进度分别展示，进度 100% 不作为任务完成依据。
- Active Backup for Business 保持只读；本批不包括恢复、删除任务、编辑计划、远程／云端目标创建或密钥管理。

## 创建与故障处理

使用 `SYNO.API.Info` 验证 API v1 能力，按官方套件流程分两步调用 `SYNO.Backup.Repository.create` 与 `SYNO.Backup.Task.create`。本地目标来自 `SYNO.Backup.Storage.Share.Local.list`，仅可选择返回状态 0 的共享文件夹。

提交前核对现有任务名称和目标目录；拒绝源与目标在同一共享文件夹，拒绝已有同名 `.hbk` 目录。第一次写入前持久化账号隔离的待核对记录，记录名称、目标和已知仓库编号，不存储认证信息。

创建中断或响应超时不会自动重试，也不会自动删除可能已创建的仓库。用户先在 DSM 核对，再显式清除待核对提示。创建成功仅确认 NAS 返回了任务编号，不会自动执行备份。

写操作使用绑定来源身份的客户端，使用 POST，并禁止会话恢复后的自动重放。执行操作前再次查询实时状态；成功响应只表示 NAS 接受了请求。提交后若状态未改变，按钮保持待确认，用户可在 DSM 核对后解除待确认状态。取消不回滚已处理数据。

## 协议依据与局限

主要依据是[群晖官方 Hyper Backup 2.2.9-1521 套件](https://archive.synology.com/download/Package/HyperBackup/2.2.9-1521)中的创建向导、任务设置、目录选择和执行请求（API v1）。仅提取协议字段，没有将套件源代码或二进制打包进本应用。

交叉参考：[开源客户端的 Hyper Backup 实现](https://github.com/N4S4/synology-api/blob/master/synology_api/core_backup.py)和[DSM 7 任务接口捕获记录](https://github.com/pmilano1/synology-dsm-api/blob/master/docs/api-reference/hyper-backup/tasks.md)。后者没有验证创建流程，不能据此宣称当前 NAS 套件版本已通过实测。

## 验证

- 自动测试：结构化参数编码、发现版本限制、错误目标和重复名称、两阶段检查点、仓库创建后切换账号阻止后续写入、未知响应不重试、会话失效不重放、运行／暂停／等待／未知状态和进度 100% 的区分。
- 浏览器模拟：创建、执行、暂停、继续、取消、权限失败、创建第二步超时后的持久化提示、切换账号、桌面及手机宽度布局。
- 现有回归：文件、媒体、Drive、原有备份查询与安卓布局。
- **真实 NAS 待验收**：当前 DSM/Hyper Backup 版本的两阶段创建、共享文件夹与 USB 权限、同名拒绝、磁盘空间不足、实际生成 `.hbk`、备份内容可恢复、执行/暂停/继续/取消及程序关闭后的 NAS 运行状态。
- 本批未直接连接用户 NAS 执行写入，不将模拟接口测试视为真实 NAS 验收。维持 0.1.19 预览版本，不提前发布 0.1.20。
