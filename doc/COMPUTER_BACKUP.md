# Windows 电脑文件夹备份（0.1.19 预览）

本批按用户选择，先交付电脑文件夹 → NAS 的手动完整备份。后续已增加 Hyper Backup 本地／USB 目标创建及执行管理，详见 [HYPER_BACKUP.md](HYPER_BACKUP.md)；恢复操作仍未接入。Android 保留原有手机相册备份，不显示 Windows 本地目录入口。

## 使用

1. 备份中心 → 新建电脑备份，填写名称，选择本地目录和已有 NAS 目录。
2. 保存任务后点击“执行备份”并确认。
3. 每次执行在 NAS 目标目录下创建独立的 `SynoLink-<运行编号>` 目录，包含子目录和空目录；上传不覆盖同名文件。
4. 每个文件先计算本地 SHA-256，再流式上传，最后读取 NAS 文件核对长度和 SHA-256。仅校验通过的文件计入完成数量，全部成功才标记完成。
5. 取消或错误保留本次已上传文件，不删除源文件或 NAS 文件。再次执行是新的一次完整备份，不是断点恢复。

## 边界与状态

- 原生 Rust 执行，离开备份页面或最小化窗口不停止任务；关闭整个应用或切换登录会话会中断。
- 配置与最近执行状态保存在应用数据目录 `computer-backups.json`，按服务器和账号隔离。凭据只使用内存会话，不写入任务文件。
- 进程重启时运行状态恢复为“已中断”，不会自动重复上传；用户重新登录来源账号后手动执行。
- 一次执行一个电脑备份，流式读写使用 64 KiB 缓冲；最多扫描 20 万个项目。
- 不跟随符号链接和 Windows 重解析点（包括部分云端占位文件）。不可读文件或源文件大小/修改时间变化会停止并提示，不静默跳过。
- 这不是 VSS 文件系统快照；执行期间请暂停编辑源目录。新增文件需要下一次执行才能备份。
- 暂不支持定时、增量、自动重试、保留策略、直接恢复到电脑。NAS 内容校验会产生回读流量。

## 本批验证

- 原生单测：目标路径校验、扫描空目录、检测源文件变化、取消扫描、multipart 文件名编码。
- 原生本地 HTTP 集成测试：真实本地文件经流式 multipart 上传，检查禁止覆盖参数；正确文件通过校验，篡改响应校验失败。
- 浏览器使用真实 Vue 组件与模拟 IPC：本地目录选择取消、NAS 目录选择、保存、执行确认、进度、取消、权限失败、长文件名、账号切换。
- Drive 与文件页桌面共用双色文件夹组件，Android 共用 FileTypeIcon，避免图标样式分叉。
- **待真实 NAS 验证**：上传接口的套件版本差异、只读目录、磁盘配额与空间不足、长路径/大文件、网络中断后 NAS 实际目录、进程终止后重开、SHA-256 与原文件独立核验。
- **待设备验证**：安卓视觉与现有相册备份原生行为。浏览器模拟不替代真机测试。
